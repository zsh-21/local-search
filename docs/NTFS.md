### 一、整体适配原则（Windows 10/11 全版本）
核心围绕 **API 向下兼容**、**权限自适应**、**日志版本动态适配** 三大原则，结合「原生桥接实现 USN 极速扫描 + 纯 JS 降级兜底」的落地方案，确保从 Windows 10 1507 到 Windows 11 24H2 全版本可用，整体方案分为 7 个核心模块：

### 二、核心模块实现方案
#### 1. 系统环境检测模块
- **目标**：提前识别系统版本、NTFS 分区状态、权限等级、原生插件可用性，规避兼容性问题
- **实现方式**：
  - **系统版本检测**：
    - 优先通过 `kernel32.dll` 的 `GetVersionExW`/`VerifyVersionInfoW` 动态检测 Windows 版本（区分 10/11 及子版本）；
    - 兜底方案（纯 JS）：读取 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion` 注册表或 `os.release()` 识别版本，兼容无原生插件场景。
  - **磁盘分区检测**：
    - 原生层：调用 `kernel32.dll` 的 `GetVolumeInformationW` 检测分区格式；
    - 纯 JS 兜底：执行 `child_process.exec('fsutil fsinfo volumeinfo [盘符]')` 解析输出，仅对 NTFS 分区启用 USN 日志，FAT32/ExFAT 直接降级为常规扫描。
  - **权限与插件检测**：
    - 检测进程权限等级（管理员/普通用户），普通用户自动跳过系统盘敏感目录；
    - 检测 `node-ffi-napi`/原生模块是否可用，不可用则直接触发纯 JS 降级逻辑。

#### 2. USN 日志适配模块（核心，融合原生桥接+纯 JS 降级）
- **目标**：兼容 Windows 10/11 不同 USN 日志版本（V2/V3），同时解决「纯 JS 无法实现 USN 扫描」的底层限制
- **实现方式**：
  - **原生桥接层（极速模式）**：
    - 技术选型：优先用 `node-ffi-napi` + `ref-napi` 调用 Windows API（无需编译 C++，适配性最强），备选 `node-addon-api`（C++ 原生模块，性能更高）；
    - 版本适配：动态检测 USN 日志版本，Windows 11 先尝试 V3，失败则降级为 V2（兼容 Windows 10 全版本）；
    - 多盘符适配：遍历所有 NTFS 分区，而非仅固定 C 盘，适配不同用户磁盘布局；
    - 日志启用容错：Windows 10 部分版本禁用 USN 日志时，管理员权限自动触发「启用日志」逻辑，无权限则降级。
  - **纯 JS 降级层（基础模式）**：
    - 无原生插件时，放弃 USN 扫描，改用 `fs.promises` 递归扫描用户目录（`C:\Users`），预构建 Orama 索引并持久化；
    - 路径重建优化：通过 `path` 模块解析文件路径，替代 USN 日志的「父文件引用号」逻辑，保证路径准确性。

#### 3. 权限适配模块
- **目标**：兼容管理员/普通用户权限，适配 UAC 控制策略，覆盖原生/纯 JS 双场景
- **实现方式**：
  - **权限自检**：
    - 原生层：调用 `advapi32.dll` 的 `CheckTokenMembership` 检测管理员权限；
    - 纯 JS 兜底：执行 `net session` 命令，通过返回码判断权限等级；
    - 无管理员权限时，弹窗提示（可选），或自动降级为「仅扫描用户目录」。
  - **目录过滤**：
    - Windows 10/11 系统保护目录（如 `Windows/System32`）仅管理员可访问，普通用户自动跳过；
    - 注册表访问适配：同时读取 `HKLM\SOFTWARE` 和 `HKLM\SOFTWARE\WOW6432Node`，兼容 32/64 位系统，保证应用列表完整。

#### 4. 索引构建与维护模块
- **目标**：基于 Orama 构建稳定、跨版本的文件/应用索引，兼顾极速模式与降级模式
- **实现方式**：
  - **全量索引初始化**：
    - 极速模式（管理员+NTFS+原生插件）：通过 USN 日志极速构建全量索引；
    - 基础模式（普通用户/非 NTFS/无插件）：纯 JS 递归扫描用户目录，预构建索引并持久化到 `app.getPath('userData')`；
  - **增量更新**：
    - 极速模式：监听 USN 日志增量，实时更新索引；
    - 基础模式：用 `chokidar` 监听用户目录文件变更，实时更新索引，弥补无 USN 日志的实时性不足；
  - **索引修复**：
    - Windows 11 部分版本 USN 日志截断时，自动检测索引异常并触发增量重建；
    - 纯 JS 模式下，索引文件损坏时，自动重新扫描并重建索引。

#### 5. 应用搜索适配模块
- **目标**：兼容 10/11 应用安装路径、注册表结构差异，覆盖原生/纯 JS 双场景
- **实现方式**：
  - **多源获取应用信息**：
    - 注册表：读取 `Uninstall` 项（10/11 通用）、Windows 11 新增的 `Microsoft.Windows.AppxDeployment` 相关项；
    - 开始菜单：扫描 `%AppData%\Microsoft\Windows\Start Menu\Programs`（10/11 通用）；
    - Microsoft Store 应用：读取 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\FolderDescriptions`，适配 11 内置应用；
  - **应用启动适配**：
    - Windows 11 对 UWP 应用启动参数优化，自动拼接正确的启动路径（区分 `.exe`/`.msix`/`.appx`）；
    - 纯 JS 模式下，通过 `child_process.exec` 执行应用路径，兼容 10/11 启动逻辑。

#### 6. 降级兜底模块（强化纯 JS 兜底逻辑）
- **目标**：极端场景（无原生插件、USN 日志禁用、非 NTFS 分区、权限不足）保证基础功能可用
- **实现方式**：
  - **分级策略**：
    - 优先级 1：管理员+NTFS+原生插件 → USN 日志（极速）；
    - 优先级 2：普通用户+NTFS+原生插件 → 仅用户目录 USN 日志；
    - 优先级 3：无原生插件/非 NTFS → 纯 JS 预构建索引 + `chokidar` 增量更新；
    - 优先级 4：所有模式失败 → 纯 JS 实时递归扫描（仅小范围搜索）。
  - **超时保护**：
    - Windows 10 老旧版本 USN 读取/纯 JS 扫描卡顿时，设置 30s 超时机制，超时自动切换为轻量扫描；
  - **错误兜底**：
    - 任何模块失败时，自动降级为「用户目录轻量递归扫描」，保证搜索功能不中断。

#### 7. 渲染层交互适配
- **目标**：兼容 Windows 10/11 窗口样式、交互逻辑，纯手写样式无 UI 库依赖
- **实现方式**：
  - 窗口样式：适配 Windows 11 圆角窗口、云母效果（仅 11 生效），Windows 10 降级为常规样式；
  - 快捷键适配：兼容 10/11 系统快捷键（如 Win+S 搜索冲突），可自定义快捷键；
  - 结果展示：Windows 11 应用图标高 DPI 适配，自动缩放图标尺寸，避免模糊；纯 JS 模式下通过 `fs` 读取图标文件，保证展示一致性。

### 三、部署与测试适配（融合原生/纯 JS 测试）
- **编译适配**：
  - 使用 Electron ≥28.x，编译时同时生成 32 位/64 位安装包（适配 Windows 10 32 位）；
  - 打包时可选是否包含原生模块（`node-ffi-napi`），无原生模块时自动启用纯 JS 降级逻辑。
- **测试覆盖**：
  - 系统版本：Windows 10（1507/1809/21H2）、Windows 11（21H2/22H2/24H2）；
  - 权限场景：管理员/普通用户、域账号/本地账号；
  - 磁盘场景：单 NTFS 盘、混合 NTFS/FAT32 盘、多盘符；
  - 插件场景：有原生模块/无原生模块（验证降级逻辑）；
- **异常测试**：
  - 禁用 USN 日志、删除索引文件、低磁盘空间、原生模块加载失败等场景，验证降级逻辑有效性。

### 总结
1. 核心适配逻辑：**先检测（系统/权限/插件）→ 后适配（原生 USN/纯 JS 预构建）→ 再降级（实时递归扫描）**，优先用原生桥接实现 USN 极速搜索，无插件时用纯 JS 兜底，兼容 Windows 10/11 全版本；
2. 关键保障：原生/纯 JS 双模式切换 + 权限自适应 + 日志版本动态检测，确保全版本「可用」为基础，「极速」为优化；
3. 落地核心：绕开「纯 JS 无法实现 USN 扫描」的底层限制，通过「原生桥接为主、纯 JS 兜底为辅」的方案，兼顾性能和兼容性。
