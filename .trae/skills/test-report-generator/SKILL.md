# 测试报告生成器

## 功能说明

此 SKILL 用于自动化生成测试报告，将测试结果整理成结构化的 Markdown 文档。

## 触发条件

**当用户说以下任意内容时立即调用此 SKILL：**

- "生成测试报告"
- "创建测试报告"
- "输出测试结果"
- "生成测试文档"

## 执行流程

### 1. 收集测试信息

从最近的测试执行中收集：

- 测试类型（Everything 集成、功能测试等）
- 测试时间
- 测试环境信息
- 测试结果数据

### 2. 生成报告文件名

**命名规则：**

- 根据测试内容或用户描述的问题生成
- 使用 3\~8 个中文字符
- 格式：`<测试主题>_<日期>.md`

**示例：**

- `Everything 集成测试_20260315.md`
- `搜索功能验证_20260315.md`
- `盘符索引检查_20260315.md`
- `权限问题排查_20260315.md`

### 3. 创建报告目录

```bash
# 检查 test-md 文件夹是否存在
if [ ! -d "test-md" ]; then
  mkdir -p test-md
fi
```

## 报告质量要求

### 内容完整性

- ✓ 包含所有测试结果
- ✓ 包含环境信息
- ✓ 包含问题分析
- ✓ 包含解决方案
- ✓ 包含代码示例

### 格式规范性

- ✓ 使用 Markdown 格式
- ✓ 层级结构清晰
- ✓ 代码块有语法高亮
- ✓ 使用 emoji 标记状态
- ✓ 包含时间戳

### 语言要求

- ✓ 使用中文编写
- ✓ 技术术语保持英文
- ✓ 简洁明了
- ✓ 专业规范

## 示例调用

### 场景 1: Everything 集成测试后

**用户**: "生成报告"
**SKILL 响应**:

1. 分析最近的 Everything 集成测试结果
2. 生成文件名：`Everything 集成测试_20260315.md`
3. 创建完整报告到 `test-md/Everything 集成测试_20260315.md`
4. 回复用户："测试报告已生成：test-md/Everything 集成测试\_20260315.md"

### 场景 2: 特定问题排查后

**用户**: "生成报告，关于搜索不到其他盘符的问题"
**SKILL 响应**:

1. 分析搜索结果和盘符相关测试
2. 生成文件名：`盘符搜索问题_20260315.md`
3. 创建问题排查报告
4. 回复用户："测试报告已生成：test-md/盘符搜索问题\_20260315.md"

## 注意事项

1. **文件名长度**: 严格控制在 3\~8 个中文字符（不含日期后缀）
2. **目录检查**: 始终检查 test-md 文件夹是否存在
3. **结果准确性**: 基于实际测试数据生成报告，不编造数据
4. **问题定位**: 如有失败测试，必须包含问题分析
5. **代码引用**: 必须包含具体的文件路径和行号
